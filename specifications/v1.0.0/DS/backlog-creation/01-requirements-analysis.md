## 1. 필요 기능 요구사항 작성

### 1.1 핵심 목표

사용자가 **두 가지 방법**으로 백로그를 생성할 수 있는 시스템을 구축한다:

1. **간단하게 만들기**: 명확한 작업 내용을 직접 입력하여 빠르게 1개의 백로그 생성
2. **AI로 구체화하기**: 막연한 아이디어를 AI와 대화하며 INVEST 원칙에 맞게 구체화하고, 필요시 여러 개로 분할하여 생성

### 1.2 사용자 스토리

| ID | 역할 | 목표 | 이유 |
|----|------|------|------|
| US-01 | 사용자 | 명확한 작업을 폼에 직접 입력하여 빠르게 백로그를 생성하고 싶다 | 이미 구체적인 내용을 알고 있어 빠른 입력이 필요함 |
| US-02 | 사용자 | 막연한 아이디어를 AI와 대화하며 실행 가능한 백로그로 만들고 싶다 | 아이디어는 있지만 구체화가 필요하고 INVEST 원칙을 적용하고 싶음 |
| US-03 | 사용자 | AI가 큰 작업을 작은 단위로 분할 제안해주길 원한다 | 관리 가능한 크기로 나누어 진행하고 싶음 |
| US-04 | 사용자 | 대화 중 페이지를 이탈해도 나중에 복구하고 싶다 | 실수로 페이지를 닫거나 네트워크 문제로 중단되어도 작업을 잃지 않고 싶음 |

## 2. 전체 맥락 파악 (추상화 - 큰 그림)

### 2.1 시스템 개요

백로그 생성 시스템은 **사용자의 작업 명확도**에 따라 **두 가지 경로**를 제공하는 이원화 구조입니다.

```mermaid
graph TB
    User[사용자] --> Decision{작업 내용이<br/>명확한가?}

    Decision -->|Yes<br/>빠른 입력 필요| Path1[경로 1: 간단 생성]
    Decision -->|No<br/>구체화 필요| Path2[경로 2: AI 생성]

    Path1 --> Simple[폼 직접 입력]
    Simple --> Result1[1개 백로그 생성]

    Path2 --> Chat[AI 대화]
    Chat --> INVEST[INVEST 원칙 적용]
    INVEST --> Split{작업 크기 판단}
    Split -->|적절| Result2[1개 백로그 생성]
    Split -->|큼| Result3[N개 백로그 생성]

    Result1 --> Done[완료]
    Result2 --> Done
    Result3 --> Done

    style Path1 fill:#e3f2fd
    style Path2 fill:#f3e5f5
    style INVEST fill:#fff3e0
```

### 2.2 핵심 개념

| 개념 | 설명 | 역할 |
|------|------|------|
| **이원화 진입점** | 간단 생성 vs AI 생성 | 사용자의 상황에 맞는 최적 경로 제공 |
| **INVEST 원칙** | Independent, Negotiable, Valuable, Estimable, Small, Testable | 백로그 품질 보장 기준 |
| **적응형 분할** | AI가 작업 크기에 따라 1개 또는 N개 제안 | 관리 가능한 크기로 자동 조정 |
| **세션 연속성** | 대화 세션 저장 및 복구 | 작업 중단 시에도 데이터 보존 |

### 2.3 시스템 경계

**포함 범위:**
- 백로그 생성 (간단/AI 방식)
- AI 대화 인터페이스
- INVEST 원칙 기반 품질 검증
- 작업 분할 제안
- 세션 관리 및 복구

**제외 범위:**
- 백로그 수정/삭제
- 백로그 상태 변경 (TODO → IN_PROGRESS 등)
- 스토리 포인트 추정
- 팀원 할당
- 댓글 및 첨부파일

### 5.5 F-3.3 INVEST 검증

#### 5.5.1 기능 개요

| 항목 | 내용 |
|------|------|
| **목적** | AI가 INVEST 원칙 충족 여부를 판단하여 백로그 품질 보장 |
| **트리거** | AI 응답 생성 시 (메시지마다) |
| **결과** | 백로그 초안 생성 또는 추가 질문 |
| **우선순위** | P0 (필수) |

#### 5.5.2 INVEST 원칙 체크리스트

| 원칙 | 영문 | 판단 기준 | AI 질문 예시 |
|------|------|----------|-------------|
| **I** | Independent | 작업 범위가 명확히 정의됨 | "이 작업은 다른 작업과 독립적으로 진행 가능한가요?" |
| **N** | Negotiable | 목표는 명확하지만 방법은 열려있음 | "구현 방법을 여러 가지로 고려할 수 있나요?" |
| **V** | Valuable | 작업의 목적과 기대 효과가 설명됨 | "이 작업을 통해 얻고자 하는 결과는 무엇인가요?" |
| **E** | Estimable | 작업 내용이 충분히 구체적 | "작업 범위가 명확히 정의되어 있나요?" |
| **S** | Small | 너무 크지 않고 관리 가능한 크기 | "이 작업은 한 주 안에 완료 가능한 크기인가요?" |
| **T** | Testable | 완료 조건이 구체적으로 정의됨 | "어떤 상태가 되면 '완료'라고 할 수 있을까요?" |

#### 5.5.3 검증 플로우

```mermaid
flowchart TD
    Start[대화 진행] --> CheckI{I: Independent}

    CheckI -->|미충족| AskI[AI 질문: 작업 범위 명확화]
    CheckI -->|충족| CheckV{V: Valuable}

    AskI --> WaitI[사용자 응답 대기]
    WaitI --> Start

    CheckV -->|미충족| AskV[AI 질문: 목적 및 기대 효과]
    CheckV -->|충족| CheckE{E: Estimable}

    AskV --> WaitV[사용자 응답 대기]
    WaitV --> Start

    CheckE -->|미충족| AskE[AI 질문: 작업 내용 구체화]
    CheckE -->|충족| CheckS{S: Small}

    AskE --> WaitE[사용자 응답 대기]
    WaitE --> Start

    CheckS -->|너무 큼| F3_4[F-3.4 작업 분할 제안]
    CheckS -->|적절| CheckT{T: Testable}

    F3_4 --> CheckT

    CheckT -->|미충족| AskT[AI 질문: 완료 조건 정의]
    CheckT -->|충족| Generate[백로그 초안 생성]

    AskT --> WaitT[사용자 응답 대기]
    WaitT --> Start

    Generate --> Preview[F-3.5 미리보기 표시]
```

#### 5.5.4 AI 검증 프로세스

AI는 대화 중 다음을 체크합니다:

| 단계 | 검증 항목 | 충족 시 | 미충족 시 |
|------|----------|---------|----------|
| 1 | Independent: 작업 독립성 | 다음 단계 진행 | 작업 범위 명확화 질문 |
| 2 | Valuable: 가치 및 목적 | 다음 단계 진행 | 목적 및 기대 효과 질문 |
| 3 | Estimable: 구체성 | 다음 단계 진행 | 작업 내용 구체화 질문 |
| 4 | Small: 작업 크기 | 다음 단계 진행 | 작업 분할 제안 (F-3.4) |
| 5 | Testable: 완료 조건 | 백로그 초안 생성 | 완료 조건 정의 질문 |

**모든 원칙 충족 시**: 백로그 초안 생성 (제목, 설명, 완료 조건)
**작업이 큰 경우**: 논리적 단위로 분할 제안

### 5.6 F-3.4 작업 분할

#### 5.6.1 기능 개요

| 항목 | 내용 |
|------|------|
| **목적** | 큰 작업을 Small 원칙에 맞게 작은 단위로 분할 |
| **트리거** | INVEST 검증 중 Small 원칙 미충족 |
| **결과** | N개의 백로그 초안 생성 |
| **우선순위** | P1 (중요) |

#### 5.6.2 분할 판단 기준

| 조건 | 임계값 | 동작 |
|------|--------|------|
| 작업 설명 길이 | 500자 이상 | 분할 고려 |
| 완료 조건 개수 | 5개 이상 | 분할 고려 |
| 키워드 감지 | "그리고", "또한", "및" 3회 이상 | 분할 제안 |
| 명시적 요청 | "여러 개", "나눠서" 등 | 즉시 분할 |

#### 5.6.3 분할 제안 플로우

```mermaid
flowchart TD
    Start[INVEST Small 체크] --> Judge{작업 크기<br/>판단}

    Judge -->|적절| Single[단일 백로그 초안]
    Judge -->|큼| Analyze[작업 분석]

    Analyze --> Identify[논리적 단위 식별]
    Identify --> Count{분할 개수}

    Count -->|2-3개| Suggest2[AI: N개로 나누는 것이 어떨까요?]
    Count -->|4-5개| Suggest4[AI: 작업이 많아 N개 제안합니다]
    Count -->|6개 이상| Warning[AI: 매우 큰 작업입니다. N개 권장]

    Suggest2 & Suggest4 & Warning --> Present[각 백로그 요약 제시]

    Present --> UserChoice{사용자 응답}

    UserChoice -->|"좋아요"| GenerateMulti[N개 백로그 초안 생성]
    UserChoice -->|"아니요"| Single
    UserChoice -->|"N개는 많아요"| Adjust[AI: 몇 개가 적당할까요?]

    Adjust --> UserCount[사용자가 개수 지정]
    UserCount --> Regenerate[조정된 개수로 재분할]
    Regenerate --> Present

    Single --> Preview1[단일 미리보기]
    GenerateMulti --> PreviewN[여러 미리보기]
```

| 3 | 다크 모드 지원 | 전체 페이지 다크 모드 테마 추가 | 토글로 전환 가능 |

### 5.7 F-3.5 미리보기

#### 5.7.1 기능 개요

| 항목 | 내용 |
|------|------|
| **목적** | 백로그 생성 전 내용 확인 및 수정 기회 제공 |
| **트리거** | INVEST 검증 완료 및 백로그 초안 생성 |
| **결과** | 사용자 확인 후 생성 또는 대화 계속 |
| **우선순위** | P0 (필수) |

#### 5.7.2 미리보기 타입

| 타입 | 조건 | 레이아웃 | 버튼 텍스트 |
|------|------|---------|------------|
| **단일** | 1개 백로그 초안 | 우측 40% 패널 | "백로그 생성" |
| **여러** | N개 백로그 초안 | 우측 40% 패널 (스크롤) | "N개 백로그 생성" |

#### 5.7.3 미리보기 UI 구조

```
┌─────────────────────────────────────────┐
│  채팅 화면 (60%)   │  미리보기 (40%)    │
├────────────────────┼────────────────────┤
│                    │ 📋 백로그 미리보기  │
│  [대화 내역]       │                    │
│                    │ 제목               │
│  [사용자] ...      │ ─────────────────  │
│  [AI] ...          │ [백로그 제목]      │
│                    │                    │
│                    │ 설명               │
│                    │ ─────────────────  │
│                    │ [설명 내용]        │
│                    │                    │
│  [입력창]          │ 완료 조건          │
│                    │ ─────────────────  │
│                    │ [완료 조건]        │
│                    │                    │
│                    │                    │
│                    │   [백로그 생성] → │
└────────────────────┴────────────────────┘
```

#### 5.7.4 실시간 업데이트

| 트리거 | 동작 | 애니메이션 |
|--------|------|-----------|
| 새 백로그 초안 생성 | 미리보기 패널 슬라이드인 | 우측에서 좌측으로 200ms |
| 사용자가 추가 메시지 전송 | 미리보기 내용 업데이트 | 페이드 아웃/인 300ms |
| AI가 분할 제안 수락 | 단일 → 여러 미리보기 전환 | 크로스 페이드 400ms |
| 대화 계속 시 내용 변경 | 변경된 필드만 강조 표시 | 노란색 하이라이트 2초 |

### 5.8 F-3.6 백로그 생성 (AI)

#### 5.8.1 기능 개요

| 항목 | 내용 |
|------|------|
| **목적** | AI로 구체화한 백로그를 저장 |
| **트리거** | 미리보기에서 '백로그 생성' 버튼 클릭 |
| **결과** | 1개 또는 N개 백로그 생성 완료 |
| **우선순위** | P0 (필수) |

#### 5.8.2 생성 타입별 처리

| 타입 | 요청 데이터 | 결과 | 이동 페이지 |
|------|------------|------|------------|
| **단일** | 세션 ID, 백로그 데이터 (제목, 설명, 완료 조건) | 1개 백로그 생성 | 백로그 상세 페이지 |
| **여러** | 세션 ID, 여러 백로그 데이터 배열 | N개 백로그 일괄 생성 | 백로그 목록 페이지 |

#### 5.8.3 생성 플로우

```mermaid
sequenceDiagram
    participant U as 사용자
    participant UI as 사용자 인터페이스
    participant System as 시스템

    U->>UI: '백로그 생성' 버튼 클릭
    UI->>UI: 버튼 비활성화 + 로딩 표시
    UI->>System: 백로그 생성 요청

    System->>System: 세션 검증 (상태 = IN_PROGRESS)
    System->>System: 백로그 데이터 검증
    System->>System: 백로그 저장
    System->>System: 세션 상태를 COMPLETED로 변경

    alt 성공
        System-->>UI: 생성 완료 + 백로그 데이터
        UI->>UI: 세션 정보 정리
        UI->>UI: 성공 피드백 표시
        UI->>U: 해당 페이지로 이동
    else 실패
        System-->>UI: 오류 정보
        UI->>UI: 버튼 재활성화
        UI->>UI: 에러 메시지 + [재시도] 버튼
        U->>UI: [재시도] 클릭
        UI->>System: 재요청
    end
```

#### 5.8.4 에러 처리

| 에러 유형 | 원인 | 사용자 메시지 | 복구 방법 |
|----------|------|--------------|----------|
| 유효성 검증 실패 | 데이터 형식 오류 | "입력 내용을 다시 확인해주세요" | [재시도] - 대화 계속 |
| 세션 없음 | 세션 만료 또는 삭제됨 | "세션이 만료되었습니다" | 새 세션 생성 안내 |
| 세션 이미 완료 | 중복 생성 시도 | "이미 생성된 백로그입니다" | 목록 페이지로 이동 |
| 저장 오류 | 시스템 오류 | "일시적인 오류가 발생했습니다" | [재시도] - 데이터 유지 |
| 서비스 불가 | 시스템 점검 중 | "서버 점검 중입니다" | 안내 메시지 |

### 5.9 F-4.1 에러 처리 (공통)

#### 5.9.1 에러 분류 체계

```mermaid
graph TD
    Error[에러 발생]

    Error --> Type{에러 타입}
```

| 권한 없음 | P1 | 안내 메시지 | - | - |
| 리소스 없음 | P1 | [목록으로] | - | - |
| 시스템 오류 | P0 | [재시도] | - | 데이터 유지 |
